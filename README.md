# ReCoin

Разбирает банковскую выписку и показывает, сколько денег вы потратили на самом деле.

Банк складывает в «расходы» всё подряд: переводы себе на вклад, возврат долга приятелю,
погашение кредитки. ReCoin вычитает это и оставляет только настоящие траты.
На реальной годовой выписке разница получилась в полтора раза: банк насчитал
1 221 292 ₽, потрачено – 853 232 ₽.

## Запуск

```bash
./run.sh
```

Откроется на http://127.0.0.1:8420. Первый запуск создаст окружение и поставит зависимости.

Гость видит витрину с описанием и формой входа. После регистрации открывается
кабинет: загрузка выписок, разбор счетов, траты, вопросы и итоговый отчёт.

Аккаунты лежат в `recoin.db` (SQLite) – только почта, имя и pbkdf2-хеш пароля.
Разобранные выписки на диск не пишутся вообще: они живут в памяти процесса и
исчезают при перезапуске сервера.

## Размещение в интернете

GitHub Pages не подойдёт, там работают только статические страницы. Нужна
площадка с поддержкой Python: Render, Fly.io, Railway или собственный сервер.

Команда запуска лежит в `Procfile`, версия языка в `.python-version`:

```
web: uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1
```

Один рабочий процесс обязателен. Разобранные выписки хранятся в памяти, при
нескольких процессах пользователь попадает то на один, то на другой и теряет
загруженные данные.

Переменные окружения задаются в панели хостинга, файл `.env` в репозиторий не
попадает. Помимо `ANTHROPIC_*` и `RECOIN_MODEL` установите `RECOIN_HTTPS=1`:
этот флаг помечает сессионную куку как `Secure`. Локально по HTTP переменная
остаётся пустой, иначе браузер откажется хранить куку и вход перестанет работать.

Файл `recoin.db` лежит на диске сервера. На тарифах без постоянного диска он
стирается при каждом развёртывании вместе со всеми аккаунтами, поэтому для
постоянной работы нужен подключённый диск или внешняя база.

## Как считает

**Переводы не являются тратой сама по себе.** Тратой является только непокрытый
остаток по контрагенту:

| Что произошло | Сальдо | Расход |
|---|---|---|
| Дал в долг 500, вернули 500 | 0 | 0 |
| Дал в долг 500, вернули 300 | −200 | 200 ₽ |
| Взял с кредитки 100, вернул 110 | −10 | 10 ₽ (обслуживание долга) |
| Взял с кредитки 100 000, вернул 92 000 | +8 000 | 0, но долг вырос на 8 000 ₽ |
| Отложил 10 000 на вклад | −10 000 | 0, это сбережения |

Долги разных людей друг друга не гасят: если Васе дали и не вернули, а Петя прислал
свои деньги – это не взаимозачёт.

**Свои счета не сваливаются в общий котёл.** У каждого своё назначение: деньги на вкладе
остаются вашими, а платёж по кредитке гасит долг. Назначение счетов приложение
спрашивает – угадать его по выписке нельзя.

**Несколько выписок сводятся вместе.** Выписка по дебетовой карте не видит покупок,
оплаченных напрямую с кредитки, поэтому долг по ней из неё не посчитать. Загрузите
выписки по всем своим счетам: номер договора есть в шапке каждой, так что переводы
между ними опознаются сами, а встречные проводки (списание в одной выписке,
зачисление в другой) не задваиваются.

**Ограничение метода:** взаимозачёт работает только внутри загруженного периода.
Долг, выданный в январе и возвращённый в марте, в месячной выписке останется расходом.

## Категории

Сначала работают правила: MCC-коды, если они есть в описании, словарь торговых сетей
и шаблоны для точек, которые платёжная система показывает кодом (`CH61085` –
это «Чижик», где 61 – код региона). Остальное разбирает Claude одним запросом
на все неизвестные названия, результат кэшируется в `merchant_cache.json`.

На годовой выписке правила закрыли 48% трат, модель довела до 74%.

## Модель

Настраивается в `.env` (см. `.env.example`):

```
ANTHROPIC_BASE_URL=https://cheapvibecode.ru   # прокси, авторизация Bearer
ANTHROPIC_AUTH_TOKEN=...
RECOIN_MODEL=claude-opus-5
```

Для прямого доступа к Anthropic оставьте `ANTHROPIC_BASE_URL` пустым и заполните
`ANTHROPIC_API_KEY` – тогда используется заголовок `x-api-key`.

Без ключа приложение работает целиком: вопросы и советы собираются по правилам
из `fallback.py`. Цифры те же, формулировки проще.

## Приватность

PDF разбирается в памяти и на диск не сохраняется. Модели уходят только названия
магазинов и суммы по категориям – без ФИО, номеров карт, счетов и телефонов.
Данные сессии живут в памяти процесса и стираются через три часа.

## Поддерживаемые выписки

Отлажено на «Справке о движении средств» Т-Банка (проверено на 2227 операциях,
итоги сходятся с напечатанными в выписке до копейки). Для других банков работает
запасной построчный разбор; если операции не распознались, приложение скажет об этом,
а не покажет пустой экран.

## Проверка

```bash
.venv/bin/python -m pytest tests/ -q
```

Логика взаимозачёта покрыта тестами, включая случаи с кредиткой и разными
названиями одного счёта.

Разобрать выписку без интерфейса:

```bash
.venv/bin/python -m app.parser путь/к/выписке.pdf
.venv/bin/python -m app.netting путь/к/выписке.pdf
```

## Структура

```
app/
  parser.py       PDF → операции
  mcc.py          справочник MCC-кодов
  categorizer.py  вид операции и категория
  netting.py      взаимозачёт переводов
  portfolio.py    сведение нескольких выписок
  analytics.py    агрегация и сводка
  agent.py        Claude: категории, вопросы, разбор
  fallback.py     то же самое на правилах, без модели
  auth.py         пользователи, пароли, сессии
  main.py         HTTP, авторизация, маршруты
  templates/      landing.html – витрина, app.html – кабинет
  static/         landing.css/js – витрина, app.css/js – кабинет
```
